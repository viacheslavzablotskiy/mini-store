## 🚀 Запуск проекта

## 1. Клонируйте репозиторий
```bash
git clone https://github.com/viacheslavzablotskiy/mini-store.git
cd mini-store
```
## 2. Установите зависимости
```bash
$ npm install
```
## 3. Создайте файл .env в корне проекта и заполните его
```bash
# Порт, на котором будет работать приложение
PORT=<port>

# Подключение к базе данных PostgreSQL:
# Локальная разработка
# Для локальной разработки достаточно указать только строку подключения `DATABASE_URL`:
DATABASE_URL="postgresql://<POSTGRES_USER>:<POSTGRES_PASSWORD>@localhost:5432/<POSTGRES_DB>?schema=public"

# Запуск через Docker Compose (имя сервиса базы в docker-compose.yml)
DATABASE_URL="postgresql://<POSTGRES_USER>:<POSTGRES_PASSWORD>@postgresql:5432/<POSTGRES_DB>?schema=public"
# В Docker Compose переменные POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB используются самим контейнером PostgreSQL
для создания пользователя и базы при старте.
POSTGRES_USER=<user>  # любое имя пользователя, которое вы задаёте для базы
POSTGRES_PASSWORD=<password>  # любой пароль, который вы задаёте для этого пользователя
POSTGRES_DB=<db>  # любое название базы данных, которое вы хотите использовать

# Настройки JWT (токены авторизации)
JWT_SECRET=<secret_token> # секрет для access-токена
JWT_EXPIRES_IN=<time> # срок жизни access-токена (например: 8m, 1h)
JWT_EXPIRES_IN_REFRESH_TOKEN=<time> # срок жизни refresh-токена (например: 7d)
JWT_REFRESH_SECRET=<refresh_jwt_token> # секрет для refresh-токена
JWT_REFRESH_NAME=<name_refresh_token_cookie> # имя cookie для refresh-токена
```
## Примените миграции базы данных
```bash
 npx prisma migrate deploy
```
## Создаёт актуальные типы и клиент для работы с базой данных
```bash
npx prisma generate
```
## 🚀 Компиляция и запуск проекта 
```bash
 npm run dev 
```

## 🐳 Запуск проекта с помощью Docker Compose
1. Убедитесь, что у вас установлен Docker и Docker Compose.
2. В корне проекта создайте файл `.env` и заполните его переменными окружения (см. раздел выше).
3. Запустите контейнеры:

```bash
docker compose up
```

## Описание решения 
### Использованные технологии
- **Node.js / NestJS** — выбраны для построения серверной части, так как NestJS обеспечивает модульность, строгую архитектуру и удобную интеграцию с TypeScript.
- **Prisma ORM** — для работы с базой данных PostgreSQL. Prisma даёт типизацию, миграции и удобный доступ к данным.
- **PostgreSQL** — надёжная реляционная база данных, хорошо подходит для e-commerce проектов, поддерживает транзакции и сложные запросы.
- **Docker / Docker Compose** — для контейнеризации и удобного запуска проекта вместе с базой данных.
- **JWT (JSON Web Token)**  —  для аутентификации и авторизации пользователей, так как это стандартный и безопасный способ управления сессиями.
- **Jest** — фреймворк для тестирования, обеспечивает юнит‑тесты, e2e‑тесты и покрытие кода.
- **Swagger** — для автоматической генерации и визуализации документации API, упрощает тестирование

### Почему именно эти технологии
- **NestJS** → строгая архитектура и масштабируемость.
- **Prisma** → упрощает работу с БД и снижает количество ошибок за счёт типизации.
- **PostgreSQL** → поддержка сложных связей и транзакций.
- **Docker Compose** → позволяет быстро поднять окружение без ручной настройки.
- **JWT** → удобный механизм авторизации, легко интегрируется с фронтендом и мобильными приложениями.
- **Jest** → удобный инструмент для тестирования, поддерживает снапшоты, мок‑объекты и асинхронные проверки.
- **Swagger** → предоставляет удобный интерфейс для работы с API, облегчает коммуникацию между фронтендом и бекендом, а также ускоряет процесс разработки.
